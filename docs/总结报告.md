## 三、关键实现

- **视频背景**：`AutoPlayVideo.jsx` 采用「720p 预览层先播 → 4K 加载完淡入」的两段式策略，避免首屏卡白。
- **多域名视频源**：`src/lib/mediaUrl.js` 按域名切换地址。GitHub Pages 走 `gh-proxy.com` 代理（国内直连 raw.githubusercontent 极慢），失败自动回退。
- **动效组件**：自建 `Reveal`、`SectionFrame`、`BorderGlow`、`AnimatedList`、`RaceVideoCard`、`SplashCursor` 等。
- **渠道栏**：进场动画 + 悬停动效，每支车队配色独立。

## 四、性能优化（核心成果）

**问题**：用户反馈「视频背景加载太慢」。

**根因**
1. 视频码率过高：4K 背景 11~13 Mbps，`about-car-vertical.mp4` 竟达 31 Mbps
2. 720p 预览层失效：`about-instant-720p.mp4` 有 17.5MB，比正片还大
3. 首屏 bug：预览层与 18MB 正片同时下载，预览被抢带宽拖死
4. GitHub Pages 国内实测带宽 130KB/s ~ 1MB/s，抖动剧烈

**处理与结果：总体积 501MB → 151MB（-70%）**

| 项 | 优化前 | 优化后 |
|---|---|---|
| 8 个预览层 | 2.7 ~ 17.5 MB | 164 ~ 516 KB（约 30 倍） |
| 9 个正片 | 最大 60 MB | 最大 25 MB（分辨率不变） |
| 首屏海报 | 363 KB | 86 KB + preload |

**编码要点**：用 `-maxrate` 卡码率，不能只靠 CRF（只调 CRF 反而变大）；选 x264 而非 videotoolbox，同码率画质更好。

**实测速度**

| 站点 | 首页 | 视频 |
|---|---|---|
| Cloudflare | HTTP 200 | 3.5 ~ 4.4 MB/s |
| GitHub Pages | HTTP 200 | 0.13 ~ 1.3 MB/s（走代理） |

## 五、部署踩坑记录（重要）

1. **Cloudflare 新版 Pages 已并入 Workers**，默认只给 `workers.dev` 域名 —— 该域名在国内被 DNS 污染（本机解析到假 IP `182.50.139.56`）。必须用 `npx wrangler@3 pages project create/deploy` 经典模式，才能拿到未被污染的 `pages.dev`。
2. **Cloudflare 单文件上限 25 MiB**：`redbull-bg-4k.mp4` 原 46MB 超限，截取 3–63s 车载圈速循环 → 21.7MB（后段是维修区，本就该去）。
3. **macOS 钥匙串坑**：`credential.helper=osxkeychain` 优先级高于项目配置，导致推送报 `Invalid username or token`。解决：`git push https://999op-mj:${GH_TOKEN}@github.com/...` 直连。
4. **单次推送 154MB 会 408 超时**，需分批（每批 ≤25MB）。
